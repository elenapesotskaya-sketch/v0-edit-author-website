# Supabase Integration Setup Guide

## Автоматическая синхронизация данных между v0 и развернутым сайтом

### Что изменилось?

Вместо ручной загрузки файлов - теперь **полностью автоматическая синхронизация** через Supabase:

- ✅ Все изменения автоматически сохраняются в облако (Supabase)
- ✅ При загрузке сайта данные автоматически синхронизируются
- ✅ Работает на обоих сайтах одновременно
- ✅ Никаких файлов не нужно загружать вручную

### Как это работает?

1. **Локальный кэш** (localStorage) - быстрый доступ на клиенте
2. **Облачная база** (Supabase) - синхронизация и резервная копия
3. **Автоматическая синхронизация** - в фоне при любом изменении

### Установка (должна быть сделана один раз)

#### Шаг 1: Запустить миграцию в Supabase

1. Откройте [Supabase Dashboard](https://app.supabase.com)
2. Выберите ваш проект
3. Перейдите в **SQL Editor**
4. Скопируйте содержимое файла `/supabase/migrations/001_create_tables.sql`
5. Выполните SQL скрипт

#### Шаг 2: Проверить окружение

Убедитесь, что переменные окружения установлены:
```
NEXT_PUBLIC_SUPABASE_URL=your_url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_key
```

### Использование

#### На v0 (редактирование рассказов):

1. Логинитесь (пароль: 1814)
2. Отредактируйте рассказы
3. Нажмите "Сохранить изменения"
4. **Автоматически синхронизируется на сайт** (и на развернутый сайт, если он подключен)

#### На развернутом сайте:

1. Все читатели видят обновленные рассказы **сразу же**
2. Комментарии и лайки синхронизируются в реальном времени
3. Если вы отредактируете на сайте - изменения попадут и в v0

### Оптимизация производительности

#### Кэширование (5 минут):
- Данные кэшируются в памяти, чтобы не запрашивать БД каждый раз
- Кэш автоматически обновляется каждые 5 минут

#### Быстрое отображение:
- Сначала показывается локальный кэш (мгновенно)
- Потом синхронизируется с БД в фоне
- Пользователь не видит задержек

#### Индексы БД:
- Оптимизированы по датам публикации
- Быстрый поиск комментариев по рассказам
- Быстрая сортировка по лайкам

### Структура данных Supabase

```
author_info
  - id (INTEGER, PRIMARY KEY)
  - name, bio, image, tagline, genre_description
  - created_at, updated_at

tales
  - id (TEXT, PRIMARY KEY)
  - title, summary, full_text, image
  - likes (INTEGER)
  - published_date, reading_time
  - created_at, updated_at

comments
  - id (TEXT, PRIMARY KEY)
  - tale_id (FOREIGN KEY → tales.id)
  - user_name, text
  - created_at
```

### Функции реального времени

#### subscribeToTalesChanges()
Подписаться на изменения рассказов (автоматически работает)

#### subscribeToAuthorChanges()
Подписаться на изменения информации об авторе (автоматически работает)

### Откат на localStorage (если нужно)

Если Supabase недоступен:
1. Система автоматически вернется к localStorage
2. Данные будут доступны локально
3. При восстановлении Supabase - синхронизация продолжится

### Устранение проблем

**Проблема**: Данные не синхронизируются
- Решение: Проверьте, что SQL миграция запущена в Supabase
- Проверьте переменные окружения (NEXT_PUBLIC_SUPABASE_URL и KEY)

**Проблема**: Медленная загрузка
- Решение: Это нормально при первой загрузке (синхронизация с БД)
- После этого будет быстро (кэш работает)

**Проблема**: "Permission denied" ошибка
- Решение: RLS политики должны позволять чтение всем
- Проверьте, что политики созданы правильно

### Резервная копия данных

Supabase автоматически делает резервные копии, но для дополнительной безопасности:

1. Экспортируйте данные регулярно
2. Сохраняйте их локально
3. Используйте Supabase backup feature

### Мониторинг

Проверяйте статус синхронизации:
- Откройте консоль браузера (F12)
- Ищите логи `[v0]` в console.log
- Они покажут все операции с БД
