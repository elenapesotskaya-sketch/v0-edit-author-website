# Решение проблемы сохранения изменений

## Проблема

Вы удаляли рассказы и редактировали их в v0, но после deploy'а на сайте продолжали видеть старые версии. Это происходило потому, что:

1. **localStorage - это только браузер**: Когда вы редактируете в v0, изменения сохраняются в localStorage браузера
2. **Deploy сбрасывает localStorage**: При развертывании нового кода, свежий браузер загружает пустой localStorage
3. **Приложение загружает DEFAULT_TALES**: Без данных в localStorage, приложение загружает hardcoded данные из `lib/store.ts`
4. **Изменения теряются**: Ваши локальные правки никогда не попадали в исходный код

## Решение

В админ-панели появились две кнопки:

### 1. **"Сохранить изменения"** (Upload icon)
- Экспортирует все ваши текущие правки
- Скачивает файл `updated-tales.ts` с обновленными рассказами
- Содержит JSON с последней версией всех рассказов

### 2. **"Выйти"** (LogOut icon)
- Закрывает админ-панель
- При выходе напоминает экспортировать изменения

## Как использовать

### Шаг 1: Редактируйте рассказы в админ-панели
```
Вход для автора → пароль 1814 → редактируйте/удаляйте рассказы
```

### Шаг 2: Сохраните все изменения перед выходом
```
Нажмите "Сохранить изменения" (кнопка с иконкой загрузки)
```

### Шаг 3: Скачается файл `updated-tales.ts`
```
Содержит формат:
export const DEFAULT_TALES: Tale[] = [...]
```

### Шаг 4: Обновите lib/store.ts в вашем репозитории
1. Откройте `/lib/store.ts` в редакторе
2. Найдите `export const DEFAULT_TALES: Tale[]`
3. Замените содержимое на содержимое из скачанного файла
4. Сохраните файл
5. Сделайте commit и push

### Шаг 5: Deploy
После push'a в GitHub, Vercel автоматически задеплоит новую версию с вашими изменениями.

## Важно

- **Каждый раз при выходе** нажимайте "Сохранить изменения"
- **Регулярно обновляйте** файл в репозитории
- **Коммитьте изменения** в GitHub для версионирования

## Почему так устроено?

В этом приложении нет базы данных. Все данные хранятся в коде (`lib/store.ts`). Это означает:

✓ Простота - нет необходимости в бэкенде или БД
✓ Быстрота - данные в памяти приложения
✓ Надежность - всё в исходном коде
✗ Требует ручного экспорта при изменениях

Это идеально для малых сайтов и портфолио, где содержимое редко меняется.
